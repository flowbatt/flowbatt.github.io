Checks
------
Both the WOFF2 and TTF were parsed with the existing local fontTools package.
Both report OS/2 usWeightClass=700, the Bold style flag, and head macStyle Bold.
Neither contains an fvar table. Both have OS/2 fsType=0.
Their Unicode character maps and horizontal glyph metrics are identical.

Coverage checked: uppercase/lowercase Latin, digits, spaces, SOH (%), cycle,
middle dot (U+00B7), mathematical minus (U+2212), en dash (U+2013), em dash
(U+2014), plus, equals, Greek capital delta, and Greek theta. All characters
currently used in MethodOverview.astro, SchematicPlot.astro, and
FlowSignal.astro are covered.

This is a text face, not STIX Two Math. It does not include every mathematical
symbol; for example, right arrow and infinity are absent. Those symbols are
not used by the current schematic text.

No system fonts were installed, no packages were installed, and no system
settings were changed. A locally installed STIX Two Text variable font was
inspected, but the official static Bold assets were selected for explicit
700-weight web embedding.

Font License 1.1 recorded above. The existing LICENSE-STIX.txt covers it.
Only the local filename is changed; the font is not modified or subsetted.

The existing local fontTools package verified usWeightClass=400, no fvar
variable-font table, and OS/2 fsType=0. Its Unicode cmap maps U+00B1 (PLUS-MINUS
SIGN) to the plusminus glyph, glyph ID 2078. U+FB03 (LATIN SMALL LIGATURE FFI)
maps to the distinct f_f_i glyph, glyph ID 666. Use this genuine 400 face for
regular-weight paper-table values so their ± symbols do not fall back to the
legacy Computer Modern TTF encoding. No system fonts or packages were installed.
